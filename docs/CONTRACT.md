# Sentinel — Integration Contract (single source of truth)

**Audience:** the backend agent, the simulator agent, and the frontend agent. Each builds against this file alone. If something is ambiguous here, the rule is: *do what this document says literally, then post the gap in `docs/GAPS.md`*. Do not invent a different shape.

**Product names:** product = **Sentinel**; device = **Sentinel Node**; node WiFi SSID = `SENTINEL-<node_id>`; incident codes = `SN-XXXX`.

**Date context:** demo day is 2026-09-12. Everything must be buildable by ~15:30 PDT.

## 0. Conventions everyone obeys

### 0.1 Ports, prefixes, processes

| Process | Port | Notes |
|---|---|---|
| Backend (FastAPI, uvicorn) | `0.0.0.0:8000` | All REST routes prefixed `/api`. WebSocket at `/live` (no prefix). |
| Simulator control HTTP | `127.0.0.1:8001` | `GET /state`, `POST /control`, `POST /relay`. Only the backend talks to it. |
| Simulator virtual-node UDP | `127.0.0.1:9000–9013` | One UDP socket per virtual node; internal to the simulator. |
| Frontend (Vite) | `0.0.0.0:5173` | Proxies `/api` → `http://localhost:8000` and `/live` → `ws://localhost:8000`. |

Frontend code never hardcodes `localhost:8000`; it calls relative `/api/...` and `ws(s)://<location.host>/live` so judges' phones on the hotspot work.

### 0.2 Response envelope

Every `/api` response, success or failure, is:

```json
{ "ok": true,  "data": { ... }, "error": null }
{ "ok": false, "data": null,    "error": { "code": "NOT_FOUND", "message": "incident SN-7K3F not found", "details": null } }
```

HTTP status matches the error code. Exception: `GET /api/export/drill/{id}.csv` returns raw `text/csv`.

| `error.code` | HTTP | When |
|---|---|---|
| `VALIDATION_ERROR` | 422 | Pydantic body/query failure. `details` = FastAPI's error list. |
| `MISSING_DEVICE_FP` | 400 | Civilian endpoint called without `X-Device-Fp`. |
| `UNAUTHORIZED` | 401 | Missing/invalid/expired bearer token. |
| `FORBIDDEN` | 403 | Valid token, wrong role or wrong tenant. |
| `DEVICE_BLOCKED` | 403 | Device fingerprint has ≥ 3 confirmed false reports. |
| `NOT_FOUND` | 404 | Resource missing. |
| `INVALID_TRANSITION` | 409 | e.g. `resolve` on an already-resolved incident, `rollcall` on an ended drill. |
| `CONFLICT` | 409 | Duplicate create (e.g. second open drill at a site). |
| `RATE_LIMITED` | 429 | > 3 open incidents per device per hour. |
| `SIM_UNAVAILABLE` | 502 | Backend could not reach the simulator on :8001. |
| `INTERNAL` | 500 | Anything else; message is the exception class name. |

FastAPI agent: install one exception handler for `HTTPException`, one for `RequestValidationError`, one for `Exception`; all emit this envelope. Route handlers return the bare `data` object and a small `ok()` wrapper adds the envelope.

### 0.3 Two clocks: sim time vs wall time

This matters. Get it right once.

- **Sim clock**: the simulator's scripted day (07:00 → 20:00). Anything *derived from a sensor reading* is stamped with sim time: `readings.ts`, `alerts.started_at/cleared_at`, `decision_log.changed_at`, `sms_log.sim_at`.
- **Wall clock**: real UTC now. Anything a *human or the server* does is wall time: `incidents.created_at`, `incident_events.at`, `drills.started_at`, `rollcalls.submitted_at`, `mesh_log.ts`, `sms_log.sent_at`, WS message `ts`.
- Sim timestamps are written as ISO 8601 with a `Z` suffix but **represent the demo's local clock**: `"2026-09-12T13:55:00.000Z"` means "13:55 on the demo day". **Frontend formats every sim timestamp with `timeZone: 'UTC'`** so 13:55 displays as 13:55. Wall timestamps are formatted in the browser's local zone.
- Every field documented below is tagged `(sim)` or `(wall)`.

### 0.4 Timestamp format

Always `YYYY-MM-DDTHH:MM:SS.mmmZ` (millisecond precision, literal `Z`). Python: `datetime.now(timezone.utc).isoformat(timespec="milliseconds").replace("+00:00","Z")`. Stored as `TEXT` in SQLite. Fixed width means ISO strings sort lexicographically, which the backend relies on for range queries.

### 0.5 IDs

- `tenants`, `sites`, `zones`, `users`, `classes`, `alerts`, `incidents`, `drills`, `rollcalls`, `sms_recipients`, `sms_log`, `incident_events`, `mesh_log`, `decision_log`: integer autoincrement.
- `nodes.id`: **string slug** (`"gym"`, `"field"`, `"w-a07"`). Simulator, backend and frontend all use the slug.
- `incidents.code`: `SN-` + 4 chars from `ABCDEFGHJKMNPQRSTUVWXYZ23456789`. Public handle; the integer id never leaves the backend.
- `msg_id` (mesh): `m-` + 8 lowercase hex, generated by whoever originates the message (backend for incidents, simulator for alarms).
- `device_fp`: opaque string ≤ 64 chars generated client-side (see 4.1).

### 0.6 Geometry and map coordinates

- `lat`/`lng` WGS84 floats (real UW-area coordinates) for the responder jurisdiction view and GPS consistency.
- `map_x`/`map_y` floats in a **1000 × 700 SVG viewBox** (`0 0 1000 700`), origin top-left. The campus SVG and the warehouse floor-plan SVG both use this viewBox. The frontend positions node dots with `map_x, map_y` and never projects lat/lng.
- Polygons (`sites.geom`, `zones.geom`) are GeoJSON `Polygon` objects stored in JSON columns. Frontend draws zones using the `map_poly` field (list of `[x,y]` in viewBox units) that sits alongside `geom`.

### 0.7 Headers

| Header | Who sends | Meaning |
|---|---|---|
| `Authorization: Bearer <token>` | admin, responder, teacher clients | See §2. |
| `X-Device-Fp: <fp>` | every phone-app request (civilian or not) | Device fingerprint. Required on `POST /api/incidents`, `GET /api/incidents/{code}`. |
| `X-Node-Id: <slug>` | phone app when the user picked "which node am I next to" | Simulates the captive-portal node stamp. UI label next to the picker: *"In production the node stamps this automatically; pick the node you are standing next to."* |
| `X-Sim-Key: sentinel-sim` | simulator → backend `/api/ingest/*` | Shared static key so random clients cannot inject telemetry. Backend reads it from `SENTINEL_SIM_KEY` (default `sentinel-sim`). |

CORS: allow all origins, all methods, all headers (demo runs over a hotspot with changing IPs).

## 1. Data model

### 1.1 SQLAlchemy 2.0 models (`backend/app/models.py`)

Async engine: `create_async_engine("sqlite+aiosqlite:///./sentinel.db")`. Enable `PRAGMA journal_mode=WAL` and `PRAGMA synchronous=NORMAL` on connect. Tables are created with `Base.metadata.create_all` at startup; no Alembic today. Seed runs when `tenants` is empty.

## 2. Auth

### 2.1 Token

Signed JSON via `itsdangerous.URLSafeTimedSerializer(secret_key=SENTINEL_SECRET, salt="sentinel-auth")`. Payload:

```json
{ "uid": 4, "role": "teacher", "tenant_id": 1, "site_id": 1, "class_id": 2 }
```

`site_id` = the tenant's first site (demo tenants have exactly one). `class_id` only for teachers. `max_age` 86400 s. Survives backend restarts (no in-memory session table), which is why we do not use opaque tokens. `SENTINEL_SECRET` env default `"sentinel-dev-secret-change-me"`.

Frontend stores the token in `localStorage["sentinel.token"]` and sends `Authorization: Bearer …`.

### 3.3 Nodes

**`GET /api/nodes?site_id=1`** (public) → `Node[]`. Without `site_id` returns all 14 nodes. The phone app uses this for the "which node am I next to" picker and shows `label` + `status`.

Node `status` rule (backend computes on read and on change):
- `offline` if `last_seen` is null
- `alert` if any open alert at the node with priority ≤ 2
- `watch` if an open priority-3 alert, or latest band ∈ {`unhealthy`,`very_unhealthy`,`hazardous`}
- else `ok`

**`GET /api/nodes/{id}`** (public) → `Node` plus `"site": {id,name,kind}`, `"zone": {id,name}`, `"ssid": "SENTINEL-gym"`, and `"banner"`: `{ "band": "very_unhealthy", "band_label": "Very unhealthy", "alert": Alert|null, "text": "FIRE DETECTED AT THIS NODE — EVACUATE" | "Air quality: Very unhealthy" }`. The phone app shows `banner` at the top of every page.

**`GET /api/nodes/{id}/readings?minutes=60&limit=500`** (auth) → 

```json
{ "node_id": "gym", "minutes": 60, "readings": [ { "ts": "...", "pm25": 247.1, "pm1": 148.2, "pm10": 321.2, "temp_c": 27.9, "rh": 44.1, "mq2_raw": 492, "rssi": -72, "battery_pct": 100 }, "..." ] }
```

Ordered ascending by `ts`. `minutes` is in **sim** minutes relative to the node's latest reading. Default 60, max 1440. `limit` default 500.

Backend sequence (order matters for the demo):
1. Validate `X-Device-Fp` (400), type/count (`count` 1–500, `text` ≤ 280 chars).
2. Resolve node from `X-Node-Id` (unknown slug → 422). `via = "node"` if present, else `"internet"`. Tenant = node's tenant, else tenant 1 (demo default for internet reports; production would use the portal's host).
3. Device history check → 403 `DEVICE_BLOCKED` if `false_flags ≥ 3`.
4. Rate limit: > 3 incidents by this fp with status ∉ {resolved,false} created in the last wall hour → 429 `RATE_LIMITED`.
5. Node flood guard: ≥ 20 incidents at this node in the last 10 wall minutes → create with `status "queued"`, still return 201 with the code, **do not** broadcast or relay.
6. Compute trust (§4), generate code (§4.4), insert incident + `created` event (ip = client addr).
7. Broadcast WS `incident_created`.
8. If `via == "node"`: fire-and-forget `POST http://127.0.0.1:8001/relay` (§7.3). Simulator failure is swallowed.
9. Return 201.

## 4. Trust score

### 4.1 Device fingerprint (frontend)

`device_fp = localStorage["sentinel.fp"]` or, if absent, `"fp-" + crypto.randomUUID().replace(/-/g,"").slice(0,24)` saved back. Also mirrored into a cookie `sentinel_fp` (1 year). The hidden dev toggle swaps it for `"demo-blocked-device"`. Sent as `X-Device-Fp` on every phone request.

### 4.2 Scoring (backend `trust.py`, pure function)

```python
def score_incident(*, node: Node | None, latest: Reading | None, history: list[Reading],
                   open_alerts: list[Alert], crowd_devices: int, reporter_role: str | None,
                   lat: float | None, lng: float | None, false_flags: int,
                   incident_type: str) -> tuple[int, str, list[dict]]:
    """Returns (score 0..100, label, breakdown). Never raises."""
```

| Layer | Rule (exact) | Points |
|---|---|---|
| `proximity` | `node is not None` (request carried a valid `X-Node-Id`) | +40 |
| `sensor` | `node` present AND `incident_type in {"fire","trapped","medical","other"}` AND ( latest `pm25 > 55` OR `temp_rise_2min > 3.0` OR `mq2_delta > 150` OR an open alert at the node with priority ≤ 3 ). `temp_rise_2min` = latest.temp_c − temp at `ts−120 s (±45 s)`; `mq2_delta` = latest.mq2_raw − median(mq2 over `[ts−30 min, ts−2 min]`). Missing history → that sub-term is false. | +30 |
| `crowd` | `crowd_devices` = count of *other* distinct `device_fp` with an incident of the same `type` at the same `node_id` created in the last 10 wall minutes (any status except `false`) | +20 × crowd_devices, cap +40 |
| `role` | `reporter_role in {"teacher","admin","responder"}` (valid bearer on the POST) | +50 |
| `gps` | `lat/lng` given AND node present: haversine ≤ 100 m → +10; > 500 m → −30; otherwise 0. No node or no GPS → 0. | +10 / −30 / 0 |
| `history` | `false_flags` for this `(device_fp, tenant_id)` | −40 × false_flags (blocked at 3 → request already rejected) |

`score = clamp(sum, 0, 100)`. **Cap rule:** if `node is None` and `reporter_role is None`, `score = min(score, 59)` (internet-only reports cannot show Verified) and a breakdown line `{"layer":"cap","points":0,"note":"No node stamp — capped at Likely"}` is appended.

Label: `score ≥ 60 → "verified"`, `30–59 → "likely"`, `< 30 → "unverified"`.

Breakdown always has exactly one entry per layer (`proximity, sensor, crowd, role, gps, history`, plus `cap` when applied), in that order, each with a human `note`, including zero-point ones. The frontend renders it as-is.

Trust is computed **once at creation**; a later crowd report does not retroactively raise earlier ones (kept simple on purpose; state it in the UI as "score at time of report").

### 4.3 Demo outcomes (what judges will see)

| Scenario | Layers | Score | Label |
|---|---|---|---|
| Judge on hotspot, picks node `gym` during LOCAL_FIRE, no GPS | +40 +30 | 70 | Verified |
| Same, second judge, same type within 10 min | +40 +30 +20 | 90 | Verified |
| Judge picks node `library` during calm | +40 | 40 | Likely |
| Internet report, no node | 0, capped | 0 | Unverified |
| Teacher logged in, no node | +50 | 50 | Likely |
| Teacher logged in at `gym` during fire | +40 +30 +50 | 100 | Verified |

### 4.4 Incident code

```python
ALPHABET = "ABCDEFGHJKMNPQRSTUVWXYZ23456789"   # 31 symbols, no 0/O/1/I/L
def new_code(existing_recent: set[str]) -> str:
    while True:
        c = "SN-" + "".join(secrets.choice(ALPHABET) for _ in range(4))
        if c not in existing_recent: return c
```

`band(pm25)`: round to 1 decimal, return first band whose `max` is `null` or `≥ pm25`. Band order index: good 0 … hazardous 5.

### 5.2 Pure evaluation function (`backend/app/engine.py`)

```python
@dataclass(frozen=True)
class AlertDecision:
    action: Literal["open", "clear"]
    kind: Literal["LOCAL_FIRE", "HAZARDOUS_SMOKE", "LOCAL_SMOKE_SUSPECT", "ACTIVITY_ADVISORY"]
    priority: int                       # 1..4
    node_id: str | None                 # None only for site-wide ACTIVITY_ADVISORY
    band_from: str | None
    band_to: str | None
    reason: str
    metrics: dict                       # {pm25, pm_rise, temp_rise, gas_delta, regional, rolling_pm25}
    at: str                             # (sim) = reading.ts

def evaluate(reading: Reading, history: list[Reading], neighbours: list[Reading],
             open_alerts: list[Alert], policy: dict, site_band: str | None) -> list[AlertDecision]:
    """Pure. history = this node's prior readings, oldest→newest, excluding `reading`.
    neighbours = latest reading of every OTHER node at the same site with ts within 5 sim-min of reading.ts.
    open_alerts = open alerts at this node (and the site-wide ADVISORY).
    site_band = current decision-card band for the site (None before first reading)."""
```

Derived quantities (all windows in **sim** seconds relative to `reading.ts`):

```
pm25_5min_ago = pm25 of history reading closest to ts−300 s, accepted only if |Δ| ≤ 45 s, else None
temp_2min_ago = temp of history reading closest to ts−120 s, accepted only if |Δ| ≤ 45 s, else None
mq2_baseline  = median(mq2_raw of history readings with ts in [ts−1800 s, ts−120 s]); None if fewer than 3
pm_rise   = reading.pm25 − pm25_5min_ago      (0 if None)   ← this is what makes a sim `jump` safe
temp_rise = reading.temp_c − temp_2min_ago    (0 if None)
gas_delta = reading.mq2_raw − mq2_baseline    (0 if None)
regional  = median(n.pm25 for n in neighbours) ; if neighbours empty → regional = reading.pm25 (so ratio test fails, no false fire)
```

Decision order (first match wins, exactly as spec §6.2):

```
if pm_rise > P.pm_rise and (temp_rise > P.temp_rise or gas_delta > P.gas_delta) and pm25 > P.regional_factor * regional:
    → open LOCAL_FIRE (1) unless already open at node
elif pm25 > P.hazardous_pm25 and regional > P.hazardous_regional:
    → open HAZARDOUS_SMOKE (2) unless already open at node
elif pm_rise > P.pm_rise and pm25 > P.regional_factor * regional:
    → open LOCAL_SMOKE_SUSPECT (3) unless already open at node, and unless LOCAL_FIRE is open at node
```

Clearing (evaluated every reading, independent of the open logic):

```
LOCAL_FIRE / LOCAL_SMOKE_SUSPECT open at node:
    clear when pm25 ≤ 1.5 * regional AND temp_rise < 1.0 for every reading in the last clear_after_minutes (3 sim min, ≥ 5 readings)
HAZARDOUS_SMOKE open at node:
    clear when pm25 < P.hazardous_regional for the last 10 sim min
```

`ACTIVITY_ADVISORY` is a **site-level** decision, handled by the caller after all nodes in a tick are processed (§5.3): when the site band index increases → `open ACTIVITY_ADVISORY (4)` with `band_from/band_to`, `node_id = worst node`; any previous open ADVISORY at the site is cleared first. When the band decreases, the open ADVISORY is cleared and no new one opens. The `reason` string is the decision-card `text`.

Reason strings (templates):
- LOCAL_FIRE: `"PM2.5 rose {pm_rise:.0f} in 5 min with {'+%.1f °C' % temp_rise if temp_rise>P else 'gas +%d' % gas_delta}; neighbours median {regional:.0f} — fire at this node, not the sky"`
- HAZARDOUS_SMOKE: `"PM2.5 {pm25:.0f} with neighbours at {regional:.0f} — regional smoke, hazardous band"`
- LOCAL_SMOKE_SUSPECT: `"PM2.5 rose {pm_rise:.0f} at this node while neighbours sit at {regional:.0f}; no heat — ask staff to check"`
- ACTIVITY_ADVISORY: decision-card `text`.

Applying decisions (caller, `ingest.py`): insert `alerts` row / set `cleared_at`; broadcast `alert` or `alert_cleared`; run SMS fan-out (§5.4) for opened priority ≤ 2; recompute node status and broadcast `node_status` if it changed.

### 5.3 Decision card (site-level)

Computed after each telemetry batch for every site that received a reading:

```
outdoor = nodes at site with indoor == false            (campus: field, parking; warehouse: none → use all nodes)
for each node in outdoor: rolling = mean(pm25 of its readings with ts in [now−rolling_minutes, now])   (now = max ts in batch)
worst_node, worst_pm = argmax rolling
new_band = band(worst_pm)
if new_band != current_band:
    insert decision_log(site_id, band_from=current_band, band_to=new_band, pm25=worst_pm, node_id=worst_node,
                        guidance=bands[new_band].guidance, text=TEXT, changed_at=now)
    emit ACTIVITY_ADVISORY open/clear per §5.2
    broadcast decision_card
```

`TEXT` templates by direction: worsening into `unhealthy` → `"Practice cancelled {HH:MM}, PM2.5 {pm:.0f} at {node_label}"`; into `usg` → `"Sensitive groups indoors {HH:MM}, PM2.5 {pm:.0f} at {node_label}"`; into `very_unhealthy` → `"All outdoor activity cancelled {HH:MM}, PM2.5 {pm:.0f} at {node_label}"`; into `hazardous` → `"Shelter in place {HH:MM}, PM2.5 {pm:.0f} at {node_label}"`; improving → `"Band improved to {label} {HH:MM}, PM2.5 {pm:.0f} at {node_label}"`; first reading → `"Monitoring started {HH:MM}, PM2.5 {pm:.0f} at {node_label}"`. `HH:MM` is sim time.

`GET /api/sites/{id}/decision-card` builds the card from the latest `decision_log` row + current rolling value.

### 5.4 SMS fan-out (simulated)

Triggered when an alert with `priority ≤ 2` opens:

```
recipients = sms_recipients where zone_id == alert.zone_id and opted_out_at is null
for r in recipients:
    skip if sms_log has a row for (r.id, alert.zone_id) with severity ≤ alert.priority and sim_at within sms_dedup_minutes   # one per recipient per zone per severity per hour; escalation (lower priority number) always goes
    insert sms_log(alert_id, recipient_id, zone_id, phone, body, severity=alert.priority, status="simulated",
                   provider_msg_id="SIM-"+8hex, sent_at=wall, sim_at=alert.started_at)
    broadcast sms_sent
```

Bodies (≤ 160 chars):
- LOCAL_FIRE: `"SENTINEL ALERT ({site}, {zone}): FIRE detected at {node_label} {HH:MM}. Evacuate {zone} to muster points. Do not re-enter. Reply STOP to opt out."`
- HAZARDOUS_SMOKE: `"SENTINEL ALERT ({site}, {zone}): Air quality HAZARDOUS (PM2.5 {pm:.0f}) {HH:MM}. Shelter indoors, close windows, run filtration. Reply STOP to opt out."`
- All-clear (severity 0): `"SENTINEL ({site}, {zone}): All clear {HH:MM}. Air quality back to {band_label}. Normal operations resume."`

All-clear rule: when the site band has been ≥ 2 levels below the band at the time of the last priority ≤ 2 alert for `all_clear_minutes` (30 sim min) continuously, send the all-clear once to every recipient who received that alert. Tracked with an in-memory `pending_all_clear[site_id] = {since_ts, alert_id}`.

Priority 3–4 alerts never send SMS (the hazardous-band SMS from spec §6.1 is covered by HAZARDOUS_SMOKE, which triggers whenever the band is hazardous regionally).

## 6. WebSocket `/live`

`ws://<host>/live?token=<bearer>&device_fp=<fp>` — both query params optional. One connection per browser tab; one channel. Server → client only, except client `{"type":"ping"}` → server `{"type":"pong"}`. **Demo shortcut: every client receives every message**; `token` is validated only to attach role/tenant to the connection for logging. Production would filter by tenant/role. The phone app connects too (it needs `incident_event` for its code and `alert`/`node_status` for its banner).

Envelope:

```json
{ "type": "reading", "ts": "2026-09-12T21:14:05.400Z", "data": { ... } }     // ts = wall time of emission
```

Reconnect: client exponential backoff 0.5 s → 8 s; on reconnect it refetches `overview` (the WS carries no replay).

### 6.1 Message types and exact `data` shapes

| `type` | `data` | When |

## 7. Simulator ↔ backend

### 7.1 Process model

`simulator/main.py` — one asyncio process:
- Loads `../shared/topology.json`; creates 14 `VirtualNode`s (8 campus + 6 warehouse), each with its own UDP socket on `127.0.0.1:9000 + index` (index = order in the file). Links = `neighbours`. UDP is used for real hop-by-hop mesh delivery between virtual nodes with a real 15 % drop; telemetry is posted straight to the backend (we do not animate telemetry hops).
- Sim clock: `sim_t` seconds since 07:00 on 2026-09-12; `sim_ts = "2026-09-12T" + HH:MM:SS + ".000Z"`. Starts **paused at 07:30** (`phase calm`) so the dashboard is green on first load; the operator presses play.
- Tick: every **30 sim seconds** for every node → one `POST /api/ingest/telemetry` with an array of 14 readings. At speed 60× that is one POST per 0.5 s wall. Speeds allowed: `1, 10, 60, 300` (default 60). Auto-pauses at 20:00.
- Control server (aiohttp or `http.server` in a thread — aiohttp preferred) on `127.0.0.1:8001`.
- Pushes `POST /api/ingest/sim-state` every 1 s wall and after each control action.
- Env: `SENTINEL_BACKEND=http://127.0.0.1:8000`, `SENTINEL_SIM_KEY=sentinel-sim`, `SIM_SPEED=60`, `SIM_DROP=0.15`, `SIM_SEED=42` (deterministic noise).

### 7.2 Scripted day

Regional outdoor PM2.5 `R(t)` (µg/m³), piecewise linear in sim clock time; `N(σ)` is per-reading Gaussian noise and each node has a fixed bias `b ∈ [−3, +3]` drawn from the seed:

| Sim time | `R(t)` | Phase name |
|---|---|---|
| 07:00 → 12:30 | 6 | `calm` |
| 12:30 → 13:00 | 6 → 20 | `calm` |
| 13:00 → 14:00 | 20 → 75 | `smoke` |
| 14:00 → 15:00 | 75 → 140 | `smoke` |
| 15:00 → 17:00 | 140 (±8 slow sine, 40-min period) | `smoke` |
| 17:00 → 19:00 | 140 → 60 | `clearing` |
| 19:00 → 20:00 | 60 → 40, then auto-pause | `clearing` |

Per-node reading at sim time `t`:

```
factor     = 1.0 if outdoor else 0.7                         # indoor attenuation (campus) ; warehouse nodes 0.5
pm25       = max(0, R(t) * factor + b + N(1.5)) + fire_pm(t) + smoke_boost(t) * factor
pm1        = 0.62 * pm25 + N(0.5)
pm10       = 1.30 * pm25 + N(1.0)
T_out(t)   = 12 + 12 * sin(pi * (h − 7) / 13)   clamped to 07:00–20:00 (h = hours since midnight; peak ≈ 24 °C at 13:30)
temp_c     = T_out(t) if outdoor else 20 + 0.25 * (T_out(t) − 20)   + N(0.15) + fire_temp(t)
rh         = (75 − 2.5 * (h − 7)) clamped ≥ 35 if outdoor else 45   + N(0.8)
mq2_raw    = round(180 + b_mq2 + 0.3 * pm25 + N(4) + fire_mq2(t))   # b_mq2 ∈ [−10, +10] per node
rssi       = node_rssi_base (−58 … −92, per node, gateway −40) + N(2), rounded
battery_pct= 100 for indoor (mains); outdoor: 92 − 0.4 * max(0, h − 16) (solar stops helping late afternoon), 1 decimal
```

Phase `phase(t)`: `calm` before 13:00, `smoke` 13:00–17:00, `clearing` after. If any fire override is active, the reported phase is `fire`.

**Overrides** (all hold until `clear`):
- `trigger_fire(node_id)` at sim time `t0`: `ramp = min(1, (t − t0)/60)`; `fire_pm = 180·ramp`, `fire_temp = 6·ramp`, `fire_mq2 = 300·ramp`. Multiple nodes may burn at once. Also sends a mesh message `kind:"alarm"` from the node to its gateway (§7.3) so the hop animation fires without a phone.
- `trigger_smoke()` at `t0`: `smoke_boost = (240 − R(t)) · min(1, (t − t0)/120)` so outdoor PM reaches ≈ 240 in 2 sim minutes → `HAZARDOUS_SMOKE` on `field` and `parking`, band `hazardous`, zone SMS.
- `clear()`: every override decays linearly to 0 over 120 sim s, then is removed. The engine clears alerts itself ~3 sim min later (§5.2); nothing is force-cleared in the backend.

**Jump targets** (`action: "jump"`): `"calm"` → 07:30; `"smoke"` → 13:55 (outdoor ≈ 70, indoor ≈ 49 → card flips to *Cancel outdoor practice, PM2.5 ~71*); `"fire"` → 14:30 **and** `trigger_fire("gym")`. Integer `t` = seconds since 07:00; `"HH:MM"` also accepted. A jump clears the backend's 5-min history gap naturally (pm_rise = 0 when no reading exists near `ts−300 s`), so jumping never creates a false LOCAL_FIRE. Jumping does **not** auto-clear fire overrides except `jump "calm"`, which clears everything.

Expected engine behaviour along the default timeline at 60× (10-min rolling average adds ≈ 5 sim-min lag to the raw crossing): band `moderate` ≈ 12:41, `usg` ≈ 13:22, `unhealthy` ≈ 13:44, `very_unhealthy` ≈ 14:52. No alerts ≤ priority 3 fire during the scripted day unless the operator triggers them; that is deliberate — "every node climbing together is the sky".

Gym fire at 14:30: `R ≈ 108`; others' median ≈ 75 (five indoor at 0.7 × 108 ≈ 75, two outdoor at 108) → gym ≈ 75 + 180 = 255 > 2 × 75 = 150 ✓, `pm_rise` ≈ 180 ✓, `temp_rise` ≈ 6 ✓ → `LOCAL_FIRE` within 3 readings (≈ 1.5 s wall). At the 15:00 plateau (R = 140, indoor 98): gym 278 > 196 ✓. Known non-demo edge: `trigger_fire` during `trigger_smoke` is marginal (348 vs 2 × 168); do not do both on stage.

### 7.3 Mesh relay (incident and alarm messages)

Backend → simulator, fire-and-forget with 2 s timeout:

```
POST http://127.0.0.1:8001/relay
{ "msg_id": "m-4f9a1c2b", "origin_node": "gym", "kind": "incident",
  "payload": { "code": "SN-7K3F", "type": "trapped", "count": 2 } }
→ 202 { "ok": true, "data": { "msg_id": "m-4f9a1c2b", "planned_path": ["gym","science","hub"], "ttl": 8 } }
```

Simulator then runs a real flood with de-dup over its UDP sockets, but reports to the backend one POST per hop attempt along the **planned BFS path** (the flood is real; reporting follows the primary path so the animation is legible):

```
for each hop (a → b) along planned_path, ttl starting at 8 and decrementing per hop:
    attempt = 1
    loop:
        wait 400 ms wall                                      # animation pacing
        if random() < SIM_DROP and attempt < 4:
            POST /api/ingest/mesh-message {..., "hop": {"from": a, "to": b, "attempt": attempt, "status": "dropped"}, "path": [...up to a], "delivered": false, "dropped_at": "a→b"}
            wait 3000 ms wall                                 # retry every 3 s
            attempt += 1
            POST /api/ingest/mesh-message {..., "hop": {"from": a, "to": b, "attempt": attempt, "status": "retry"}, ...}
            continue
        if attempt >= 4 and random() < SIM_DROP:              # 4th failure → give up
            POST {..., "status": "failed", "delivered": false, "dropped_at": "a→b"}; return
        path.append(b)
        status = "delivered" if b == gateway else "ok"
        POST /api/ingest/mesh-message {..., "hop": {"from": a, "to": b, "attempt": attempt, "status": status}, "path": path, "ttl": ttl, "delivered": status == "delivered"}
        break
```

Total animation time for a 3-hop path with no drops ≈ 1.2 s; with one drop ≈ 4.6 s. Kind `alarm` payload: `{ "alert": "LOCAL_ALARM", "pm25": 247.1, "temp_c": 27.9 }`. Kind `incident` originating at a gateway node (e.g. judge picks `hub`) still posts one `delivered` hop with `hop_from == hop_to == "hub"`, `path ["hub"]`, so the incident gets its `relayed` event.
